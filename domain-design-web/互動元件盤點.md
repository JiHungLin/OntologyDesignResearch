# 網頁互動元件盤點

> **用途**：把 Domain 設計流程中「人要和 AI 互動」的地方整理成元件，給流程網頁使用。
> **開始**：2026-10-27（分支 `web-ui`）
> **目標**：降低使用者照這套流程設計系統時的痛感——不用在 terminal 與編輯器之間切換、一眼看出 AI 要你做什麼；介面盡量簡潔，但能查閱完整文件。
> **原則**：
> 1. `.md` 仍是正本，網頁讀寫同一批檔案；`lint.py`、`md2build.py`、`sync_core.py`、凍結 tag 照常運作。
> 2. 網頁是外殼：流程規則由工具包的 skills 與 `docs/` 決定，網頁不重寫一份。
> 3. 不完全照 HR 試跑的情境設計；HR 只當參考。

## 一、盤點來源

| 來源 | 看了什麼 |
|---|---|
| 工具包 `templates/review.md`、精簡版 0.2「審查頁」「問人的方式」 | 審查頁的固定格式 |
| 工具包 `.claude/skills/domain-step` 等 8 個 skill | AI 在哪些地方停下來等人 |
| HR `annual-leave-grant/reviews/2026-10-27_02.md` | 實際的審查頁（② 回頭修改） |
| HR `annual-leave-grant/questions.md`、`06_evidence/golden_cases.md` | 專家問題、黃金案例的實際規模 |

## 二、觀察

1. **一份審查頁就很大**：② 回頭修改這一份有 9 題選擇題、25 列確認、約 14 KB。每列確認都附 `檔名:行號`，人要到編輯器打開檔案、跳到那一行看前後文——切換成本主要來自這裡。
2. **專家問題一格塞好幾題**：`questions.md` 16 題，最長的 EQ-002 約 800 字，裡面有多次「（第 ② 步追加）」的子問題，「影響」欄也很長。規範要求「一次一題」，但 EQ 在表格的一格裡無法分開。
3. **黃金案例多**：23 個，每輪請人算的最多 3 個。人算的時候要自己找規則、參數、輸入，算完還要和系統結果比對。
4. **對話中途的停止點沒有固定格式**：審查頁以外，AI 也會在對話中停下來等人，這些只出現在 terminal，是「不知道 AI 要我回答什麼」的主要來源：

   | 停止點 | 出處 |
   |---|---|
   | 開始一步前，用一句話確認要做哪一步、哪條切片 | `domain-step` 開頭 |
   | 範圍細化後和切片地圖不一致（例：要拆成兩條），請人決定 | `domain-step` ① |
   | ⑤ 先只產出 `05_mapping.md`，請人確認對照表再產生 schema 與 API | `domain-step` ⑤ |
   | 實作時發現設計問題，停下來說明 | `domain-step` ⑥ |
   | 送審後才出現的新範圍，「併入這輪／下一輪」 | 精簡版 0.2「一輪的範圍」 |
   | 要改其他切片已凍結的內容，先停下來列出受影響位置 | 精簡版 0.9 |
   | 新需求要擴充現有切片還是開新切片 | 精簡版 0.9 |

## 三、元件

每個元件寫：什麼時候出現、資料從哪裡來、人做什麼、寫回哪裡、之後誰接手。

### C1 選擇題

- **出現**：審查頁「一、要你回答的問題」；中途停止點（見 C7）；「通過後新增」。
- **資料**：審查頁的「### 問題 n（步驟 D-nn）」區塊：背景、問題、A（建議）、其他選項、其他。
- **畫面**：一次一張卡片。背景裡的出處（`inputs/…:9`、`01_scope.md:94`）可以點，在側欄（C8）打開並標出那一行；選項逐一列出「選了之後設計會怎樣」。
- **人做什麼**：點 A／B，或在「其他」寫一句。
- **寫回**：該題的「你的回答：」。
- **接手**：全部作答後，交給 AI 處理（「審查好了」）。

### C2 確認列

- **出現**：審查頁「二、要你確認的內容」。
- **資料**：表格的「要看的／原文／在哪裡」。
- **畫面**：左邊是要看的與原文，右邊直接顯示 `在哪裡` 那一段的前後文（不用另開檔案）。同一個 Entity、同一類（新增 Entity、推導值、關係）的列放在一組。
- **人做什麼**：打 ✓，或寫一句意見。
- **寫回**：該列的「確認」欄。

### C3 抽查

- **出現**：審查頁「四、抽查」。
- **資料**：可挑的完成標準（AI 自評 ✓ 的條目）。
- **畫面**：列出可挑的條目全文；選 1～2 條後，顯示該條的 AI 自評與對應的檔案內容。
- **人做什麼**：選條目，寫結果（符合／不符合＋一句）。
- **寫回**：抽查表。

### C4 結論與凍結

- **出現**：審查頁「結論」；C1～C3 全部完成後才能填。
- **畫面**：每一步一列：審查者、日期（預設今天）、結論（通過／不通過）。還沒作答的題目與確認列數量要顯示在旁邊。
- **寫回**：結論表。
- **接手**：「交給 AI 處理」或「凍結」（`/domain-freeze N`）。

### C5 黃金案例試算

- **出現**：審查頁「三、要你算的黃金案例」（只在第 ⑤ 步）。
- **資料**：`golden_cases.md` 中要人算的案例（輸入、用到的規則與參數）。
- **畫面**：輸入整理成表格；用到的規則（R-nn）、參數可以點開看全文；人填預期結果，送出後和系統結果並排比對，不一致的欄位標出來。
- **人做什麼**：填預期結果與計算說明。
- **寫回**：審查頁該案例下面留空的欄位。

### C6 專家問題（EQ）

- **出現**：`questions.md`；步驟中新增、追加。
- **畫面**：每題一張卡片，大題下面拆成子題（每個「追加」一條）；「影響」收合，展開才看。可以匯出給專家（純文字或文件），不附建議答案。
- **人做什麼**：登錄專家答覆（逐子題）、改狀態。
- **寫回**：`questions.md` 的答覆、答覆日、狀態；答覆原文存成 `inputs/`。
- **接手**：`domain-expert-reply`。
- **注意**：子題目前混在同一格裡，網頁要拆分就需要固定寫法——見「四、待決定」第 2 點。

### C7 中途停止點

- **出現**：二、第 4 點的各種停止點。
- **畫面**：用 C1 的選擇題卡片呈現，放在待辦最上面，不埋在對話裡。
- **注意**：目前停止點只存在對話中，網頁讀不到——見「四、待決定」第 1 點。

### C8 文件側欄（查閱用）

- 打開任何切片檔案、`inputs/`、`docs/`，跳到指定行並標出。
- 編號可以點：D-nn、X-nn、R-nn、EQ-nnn、GC-nn、`<切片>/<檔名> D-nn`，跳到定義的位置。
- 顯示該檔案的凍結 tag 與目前差異（回頭修改只審差異時用）。

### C9 狀態總覽

- 對應 `domain-status`：每條切片每一步的狀態、這輪要你做的事（未答的題數、未確認的列數）、待問的 EQ。
- 首頁就是這一頁：只顯示「現在輪到你做什麼」，其他收合。

### C10 和 AI 對話

- 自由輸入，處理上面的元件涵蓋不到的情況；放在畫面下方，平常收合。
- AI 回覆中有要人回答的問題時，應改用 C7 呈現，不只寫在對話裡。

## 五、AI session 管理

使用者決定（2026-10-27）：網頁用 `claude -p` 執行工具包的 skills、單人本機使用、不開資料庫。現在的用法是一條切片一個 session，換切片或換需求時開新的；網頁要接住這個做法。

**原則：記憶在檔案，不在 session。** 設計內容、審查狀態、使用者說過的話都以 `.md` 為準；網頁顯示的狀態一律從檔案算出，不依賴 session 記得什麼（精簡版「換 session 的時機」：摘要過的 session 容易憑記憶回答）。session 只放這一段工作的上下文。

1. **session 登記表**：在切片 repo 放 `.domain-web/sessions.json`（加進 `.gitignore`，不是設計內容），每一筆記：
   | 欄位 | 例 |
   |---|---|
   | 切片 | `annual-leave-grant`（流程修改、地圖規劃等不屬於切片的寫 `_plan`） |
   | 用途 | ② 回頭修改、審查、凍結 |
   | session id | 網頁用 `--session-id` 指定，所以一開始就知道 |
   | 名稱 | `-n "annual-leave-grant ②"`，在 terminal 的 `/resume` 也認得出來 |
   | 開始、最後使用 | 日期時間 |
   | 狀態 | 使用中／已結束 |
   | 交接來源 | 開這個 session 時給的交接提示（存全文） |
2. **呼叫**：`claude -p --resume <id> --output-format stream-json`，網頁顯示過程與結果。網頁和 terminal 用的是同一個 session：網頁處理不了的，可以在 terminal 執行 `claude --resume <id>` 接著做，反之亦然。
3. **同一條切片同一時間只有一個使用中的 session**；不同切片可以各有一個。同一個 session 一次只送一個請求（上一個沒結束，按鈕不能按）。
4. **什麼時候開新的 session**：照精簡版「換 session 的時機」——換切片、進入下一個階段（一步做完換下一步、審查 → 凍結、凍結 → 下一輪）、對話經過摘要壓縮、流程修改與切片設計分開。網頁偵測到這些情況時，用 C1 選擇題問「開新的 session（建議）／繼續用這個」，不自己換。
5. **交接提示由檔案產生，不由舊對話摘要**：新 session 的第一則訊息由網頁組出——切片與步驟、`domain-status` 的結果、最新的審查頁路徑、`CHANGELOG.md` 最後幾筆、未回覆的 EQ——並要求 AI 先讀這些檔案。人可以在送出前修改。
6. **子代理**（挑錯、送審前核對）由 skills 在 session 裡自己開，網頁不另外管理。
7. **待確認**：`-p` 不能互動核准權限。先用專案的權限設定（允許讀寫切片 repo、執行 `tools/*.py`），遇到要核准的動作時，網頁顯示 AI 被擋下的指令，請人到 terminal 用 `--resume` 處理；之後再看要不要做網頁上的核准。
