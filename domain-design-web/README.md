# Domain 設計流程網頁

把 Domain 設計流程中「人要和 AI 互動」的地方做成網頁，降低在 terminal 與編輯器之間切換的成本，並讓人一眼看出這輪要做什麼。設計與盤點見 [`互動元件盤點.md`](互動元件盤點.md)。

**完整一版（2026-10-28）**：從主題草案開始，引導整個 domain 的設計流程——寫方向 → AI 規劃（盤點資料、切片地圖、名詞草圖）→ 補資料、接受推想草稿、同意地圖 → 一條一條開切片 → 每一步交給 AI 產出、你在審查頁作答、凍結 → 專家問題與回頭修改。每一個「輪到 AI」的地方都是一個按鈕，AI 在背景跑，做完畫面自動更新。

## 使用

```bash
# 新的 domain：在空資料夾建立設計 repo（複製工具包、建立 slices/ 與 inputs/、.gitignore 排除 .domain-web/、git init 並做初始 commit）
python3 server.py --repo ~/Projects/my-domain --init

# 讓同一個網路的其他電腦也能開（會印出區網網址；沒有登入機制，只在信任的網路上用）
python3 server.py --repo ~/Projects/my-domain --host 0.0.0.0

# 已有的設計 repo
python3 server.py --repo <設計 repo 的路徑>    # 例：~/Projects/HR-Domain-Desing
# 打開 http://127.0.0.1:8765/
```

- 只綁 `127.0.0.1`，單人在本機使用。
- 切片 repo 的 `.gitignore` 要加一行 `.domain-web/`（AI session 登記表放在這裡，不是設計內容）；沒加時網頁左上會提醒。

## 畫面

任務板風格：整個 domain 是四段旅程（主題草案 → 規劃 → 一條一條切片 → 有系統再驗證），每條切片的六步是關卡，審查頁要做的事是任務。UX 設計稿見 Artifact「Domain 設計審查 UX」。

| 畫面 | 網址 | 內容 |
|---|---|---|
| 總覽 | `#/` | 四段旅程走到哪；現在輪到誰、做什麼（一個大按鈕）；所有切片的情境與 ①～⑥ 進度；資料清單、專家問題支線 |
| 主題草案 | `#/start` | 用自己的話寫：想做什麼、給誰用、要解決什麼、一定要做到、明確不做、有沒有專家；存成 `inputs/shared/主題草案.md`（再寫一次是加一節「補充」），然後請 AI 規劃 |
| 規劃 | `#/plan` | 方向、現實資料（待提供的可以貼上或上傳、推想草稿去看）、切片地圖（起點 → 結果）、名詞草圖（依 core／shared／domain）、待釐清與 AI 還沒人同意的決定。意見先放進「回饋籃」，一次交給 AI 改；草稿都接受了才能按「同意」 |
| 推想草稿 | `#/draft/<檔>` | 草稿內容、AI 最不確定的地方；「大致對，先當假設用」寫入「已接受為假設（你，日期）」，或寫意見 |
| 開始一條切片 | `#/new/<切片>` | 開工前的四個問題（不做什麼、專家、靜態替代、其他資料）一次回答，交給 AI 建立資料夾並做第 ① 步 |
| 切片首頁 | `#/s/<切片>` | 六步關卡；依狀態顯示：AI 在等你回答（問題卡取代關卡按鈕）／輪到你審查（任務與進度）／審查填好了（交給 AI、請 AI 凍結）／凍結還沒做完（請 AI 做完）／下一關要 AI 做什麼、之後輪到你做什麼／AI 正在做／設計完成；專家問題支線；「發現問題或新說法」交給 AI 判斷（`/domain-change`） |
| 專家問題 | `#/eq/<切片>` | 每題一張卡：還沒答覆的（待問、已問都一樣）可以複製給專家（不含建議答案）；「專家回覆了」貼上原話，存成 `inputs/<切片>/專家答覆_EQ-nnn_<日期>.md` 後交給 AI（`/domain-expert-reply`） |
| 一次一個決定 | `#/r/<審查頁>/decide/<n>` | 一題一頁：問題、例子、選項卡（「→」前是做法、後是選了之後會怎樣）、寫一句、為什麼要你決定（背景）、行內問 AI、先跳過；題號與行號收在「技術細節」 |
| 看圖確認 | `#/r/<審查頁>/confirm[/<Entity>]` | 審查頁含第 ② 步時，從 `02_entities.md` 畫模型圖：這輪改到的（確認列指到的卡與關係）放中間，綠色；點方塊看它是什麼、記什麼、為什麼要單獨記，並確認相關的列。其他確認列依「要看的」分組（「決定 D-01（…）」這種一個編號一列的，同一類放一組），可以整組打 ✓。每一列附上「在哪裡」指到的內容（伺服器從交付物拿出來，不用打開檔案）：表格列逐欄列出、主要的一欄（決定、內容…）放大、長的理由與依據收在「為什麼」；標題附那一段；「原文」摘的字句用螢光標出來，都找得到就不另外列原文；原文摘的句子（標題不算）放在卡片最上面當「要確認」；指到決定這種有主要欄位的列時，主要欄位本身就是要確認的，長的照「。」「；」拆成幾點。每一組（以及狀態圖說明欄裡的確認）附一句「要你判斷什麼」，依類別固定寫（精簡版 0.2 的表、AI 提出的決定、自評「部分」），卡片標題只留編號與主題 |
| 看圖確認（③） | 同上 | 審查頁含第 ③ 步時，從 `03_flows.md` 畫每個名詞的狀態圖（`flows.py`）：方塊是狀態（雙框是終點），箭頭上是觸發事件的中文名稱（⚙ 是系統自動），自己到自己的（更正）畫在方塊上方。點箭頭的字或說明欄的一列，看誰可以做、前提條件、規則與事件表那一列。沒有狀態的名詞另列一排，點了看它用什麼記變化。確認列指到某個名詞那一段的，放在那個名詞的說明欄 |
| 黃金案例 | `#/r/<審查頁>/golden/<n>` | 情境畫成時間軸（「要回答」問到的日期標「你來算」）；提示卡是輸入；填預期結果、計算過程、計算者；送出後才顯示設計推出的答案（紙上推演），兩邊並排；案例有「要得出」（①②…）時每一項一個填答格，存成「① …　② …」；送出後跳到下一個還沒填的案例；設計推出的答案從 `06_evidence/golden_cases.md` 的紙上推演讀 |
| 抽查與簽名 | `#/r/<審查頁>/finish` | 從可挑的條目點 1～2 條、看 AI 自評、填結果；前面都完成後簽名（通過／不通過）；最後交給 AI 或請 AI 凍結 |
| 共用核心 | `#/core[/<分頁>/<項目>]` | 唯讀，把 `core/` 整理成五個分頁：名詞與關係（關係圖，點名詞看定義、屬性、關係；可依層與文字篩選）、狀態與事件（和 ③ 看圖確認同一套狀態圖，下面是事件表與更正方式）、規則（一條一張卡，可依種類與文字篩選）、詞彙（依種類篩選）、變更紀錄。左側欄 core 底下的「共用核心（整理過的）」進入；原檔仍可在左側欄打開 |
| 檔案 | `#/f/<路徑>` | 唯讀看檔案：Markdown 排版顯示，其他文字檔原樣顯示；Excel、PDF 這類原始檔只顯示大小（AI 會直接讀）。「看行號」在右側打開 |

左側導覽列（照 Notion：側欄是獨立的一欄，從畫面頂端開始，展開時頂列往右擠；收起時頂列最左邊是 ☰，點了才展開；展開時側欄最上方左邊是收起鈕，和 ☰ 同一個位置；「DOMAIN 設計」一律在頂列，切片地圖有「領域」後前面加上主題名稱（領域的第一段，例：人資、碳管理），分頁標題也改成「人資｜Domain 設計」；Ctrl+\ 切換；窄螢幕預設收起，點內容區或選了項目就收回）：總覽、主題草案、規劃（地圖、名詞草圖、推想草稿）、每條切片（狀態；展開是首頁、審查、專家問題、①～⑥ 的檔案與狀態、其他檔案）、還沒開始的切片、`core/`、`inputs/`（依資料夾）、CHANGELOG。展開狀態記在這個瀏覽器；切片首頁上方的關卡也可以點，打開那一步的檔案。

點任何「檔名:行號」都會在右側打開檔案、標出那一行。右上角「AI」打開 AI 對話。

AI 停下來問人時（例：規劃中的取捨），最後一則回覆裡的選擇題會變成頁面上方的「AI 在等你回答」卡片，點選項就回覆；一次問好幾題時每題各選一個再送出（回覆寫成「第 1 題（…）：A」）。不是問題的回覆收成一行「AI 上次說」。切片首頁在 AI 等你回答時，問題卡取代關卡按鈕；這時從別的按鈕交代另一件事（會開新的 session），網頁先問要不要先回答（按「不用回了」就不再擋）。

步驟的「已凍結」要檔頭寫已凍結**而且**版本的 tag 存在；只有檔頭、沒有 tag 的算「凍結中」（凍結做到一半，例如 AI 改了檔頭後停下來問要不要寫入 `core/`），首頁顯示「凍結還沒做完」，不會叫你開始下一關。

審查頁問題的 `- 例子：`（具體的人、日期、數字）與可選的 `- 主題：`（題目上方的標籤），畫面會用上；選項的「做法 → 結果」拆成大字與「選了之後」。2026-10-28 起工具包的範本與 `lint.py` 要求例子與「→」（先試用）；之前的審查頁沒寫也能用。

## 前端檔案

`static/index.html` 只載入 `static/js/main.js`（瀏覽器原生的 ES modules，不用打包工具）。一頁或一組功能一個檔：

| 檔案 | 內容 |
|---|---|
| `core.js` | 共用工具與資料：`$`、`api`、`esc`／`inline`／`md`、`toast`、`state`、讀寫審查頁 |
| `main.js` | 路由與啟動（綁定頂列、抽屜、鍵盤） |
| `nav.js` | 左側導覽 |
| `ai.js` | AI 對話：session、右側抽屜、等待與進行中的卡片 |
| `files.js` | 檔案：右側抽屜與唯讀檔案頁 |
| `coreview.js` | 共用核心的閱讀頁（`core_view.py` 解析 `core/`） |
| `panzoom.js` | 圖的縮放與平移：拖曳移動、Ctrl／⌘＋滾輪或觸控板捏合縮放、－／＋、全圖、1:1；`main.js` 在 `.diagram` 裡的 svg 出現時自動掛上，重畫時保留位置與倍率 |
| `overview.js` | 總覽與主題草案 |
| `plan.js` | 規劃：加資料、切片地圖、推想草稿、開始一條切片、專家問題 |
| `home.js` | 切片首頁 |
| `decide.js`、`confirm.js`、`flows.js`、`golden.js`、`finish.js` | 審查的四個任務：決定、看圖確認（`flows.js` 是 ③ 的狀態圖）、黃金案例、抽查與簽名 |

伺服器對首頁與 `static/` 回 `Cache-Control: no-cache`，改了前端檔案重新整理就生效。

## 網頁寫入哪些檔案

網頁只寫「人做的事」，其他都交給 AI（照工具包的 skills 改）：

| 人做的事 | 寫到哪裡 |
|---|---|
| 主題草案 | `inputs/shared/主題草案.md`（檔頭「使用者於對話中提供，<日期>（流程網頁）」） |
| 貼上或上傳的資料、專家答覆原文 | `inputs/shared/` 或 `inputs/<切片>/` 的新檔（已存在的不覆寫；上傳的檔原樣保存） |
| 接受推想草稿 | 草稿開頭區的「狀態」：待接受 → 已接受為假設（<名字>，<日期>）；名字不能是 AI |
| 審查頁作答 | 見下一節 |

切片地圖的同意、回饋、待釐清的答覆、專家答覆的處理，都交給 AI 照 `domain-plan`、`domain-expert-reply` 改（記 CHANGELOG），網頁不自己改規劃文件。

## 寫回審查頁的方式

- `.md` 是正本，網頁只改人要填的地方：選擇題的「你的回答」、確認列的「確認」、黃金案例的「預期結果」「計算過程」「計算者」、抽查表、結論表。其他行不動（測試確認重寫後檔案逐字相同）。
- 每次寫入都帶著打開時的檔案摘要；檔案在那之後被改過（例：AI 正在修改）就拒絕寫入，請人重新載入。

## AI session

設計見《互動元件盤點》第五節。重點：

- 記憶在檔案，不在 session：網頁的狀態一律從 `.md` 算出。
- 一條切片同一時間一個使用中的 session，登記在 `<切片 repo>/.domain-web/sessions.json`。第一次用 `--session-id` 建立，之後用 `--resume`；在 terminal 可以 `claude --resume <id>` 接著做。
- 範圍：規劃用 `_plan`，其他用切片代號；一個範圍同一時間一個使用中的 session。
- 每個按鈕都有用途（規劃、第 N 步、審查 02、凍結 02、專家回覆、修改）。現在的 session 用途不同、或經過摘要壓縮時，網頁用選擇題問要不要開新的（精簡版「換 session 的時機」）；沒有 session 就直接開。新 session 的第一則訊息是由檔案產生的交接提示（CHANGELOG、審查頁、未回覆的 EQ）加上這件事，送出前可以改。
- **在背景跑**：送出後 `claude -p` 在伺服器端執行，事件寫進 `.domain-web/logs/<id>.jsonl`，網頁每 1.5 秒取一次。關掉或重新整理頁面不會中斷，回來接得上；做完畫面自動更新。
- **權限**：網頁用 `--permission-mode acceptEdits`（只限設計 repo 內的檔案修改）加一份允許清單：讀寫檔、子代理、skills、網路搜尋與讀取、`python3 tools/*`、`git status/diff/log/show/tag/add/commit/rev-parse`、`ls`、`cp`、`mkdir`、`curl`、`date`、`cd`，以及唯讀的 `cat`、`head`、`tail`、`wc`、`sed -n`、`echo`、`sort`、`diff`（串接的指令每一段都要在清單內才會過；系統提示也請 AI 一次一個指令、不用 for 迴圈，下載的原文放 `.domain-web/tmp/`）。另外附一個小工具 `fetch_text.py`：AI 用 `python3 <網頁資料夾>/fetch_text.py <網址> [檔名]` 下載公開來源，原文存到 `.domain-web/tmp/`，HTML、PDF 轉成同名 `.txt`（照原文、不摘要）；這是允許清單裡唯一能跑的 python（設計 repo 的 `tools/*` 之外）。被擋下的指令在 AI 對話裡收成一塊，AI 多半會改用別的方法繼續。同一個設計 repo 一次只跑一件 AI 工作（所有 session 共用同一份工作目錄與 git，CHANGELOG、`core/`、commit、tag 會互相踩到），伺服器和畫面都會擋；要多條切片平行，照流程由不同的人各自 clone、開分支、用 PR 合併。網頁也一次只做一條切片：還有切片 ①～⑤ 沒都凍結時，不能開新的切片（開切片頁只顯示「要等 X 做完」，伺服器也拒絕建立新切片的 session）；規劃不受限。注意：`cp` 只要加選項（`-r` 等）就一定要人核准（Claude Code 內建的路徑安全規則，`--allowedTools` 放行不了；2026-10-28 用 2.1.312 實測），所以系統提示請 AI 先 `mkdir -p` 再逐檔 `cp`。另外用 `--settings` 掛一個 PreToolUse hook（`readonly_hook.py`）：串接的指令（`cd …; for …; cat …`、`grep … | head`、`awk`、`sed -n`）只要每一段都只讀、讀的路徑都在設計 repo 裡就放行（`git` 只算 `status`、`diff`、`log`、`show` 等讀的子指令）；自己寫的 python（`python3 - <<EOF`、`python3 -c`）直接拒絕並在理由裡寫改用什麼（挑錯、核對的子代理拿不到 `web_prompt.md`，只能從被擋的理由學到）；其他照原本的規則。附加給 AI 的系統提示在 `web_prompt.md`，每次執行時讀，改了不用重開伺服器。清單之外、hook 沒有直接拒絕的指令（`git push`、`rm`、第 ⑥ 步的 `docker`、`pytest`、`pip`…）**在網頁上逐條核准**（2026-11-04，`docs/01` ⑥「實作指令與執行紀錄」）：`claude -p` 加 `--permission-prompt-tool mcp__web__approve`，`--mcp-config` 掛網頁附的 `approve_mcp.py`（stdio MCP）；它把請求寫成 `.domain-web/approvals/<session>/<請求>.json`，等網頁寫回 `<請求>.decision.json` 再回給 claude（等 30 分鐘沒人按就當作不放行；子程序的 `MCP_TOOL_TIMEOUT` 設 40 分鐘）。AI 對話抽屜自動打開、頂列顯示「AI 等你核准指令」，卡片寫出用途（Bash 的 description）與完整指令，人填核准人（＝⑥ 的執行者）按「放行這一次」或「不放行」（可寫原因，AI 照著改）；決定記進對話紀錄。`tools/run_evidence.py` 雖然在 `tools/` 底下，hook 一律回 `ask`，所以也要核准。注意：Claude Code 自己判定為安全的指令（例：`uname`）與 `acceptEdits` 下工作目錄內的檔案指令（例：`touch`）不會跳出核准（2026-11-04 用 2.1.318 實測）。清單可用環境變數 `DOMAIN_WEB_ALLOWED`（逗號分隔）覆寫。使用者自己的 Claude Code 設定仍然有效。
- **網頁附加的系統提示**（`--append-system-prompt`）只說明執行環境：使用者看不到選項介面，要問人時照 0.2「問人的方式」寫成「問題／例子／A（建議）：做法 → 結果／B／其他」，網頁會把它變成選擇題卡片。流程規則仍以工具包為準。
- `CLAUDE_BIN` 環境變數可以指定 `claude` 的路徑（測試用假的 `tests/fake_claude.py`）。

```bash
python3 -m pytest tests -q
```

用 `tests/fixture/` 的假資料（不含任何真實切片內容）：審查頁讀寫、模型圖、規劃解析、接受草稿、存資料、專家問題、背景執行（假的 claude）、`--init`。
