# 檢查

1. **轉出 YAML**：執行 `python3 tools/md2build.py <切片>`，把 `core/` 與這條切片的 01～04 合併轉成 `.build/` 的 YAML。不要自己寫轉換程式。
   - 程式列出的「看不懂或不合格式的列」是交付物的格式錯誤，照樣寫進回報（檔案:行號、建議怎麼改）；「提醒」是格式以外的寫法，列出即可。
   - 程式本身轉錯（Markdown 符合 `docs/02` 卻被判錯，或該抓的沒抓到）：在回報中寫明，不要繞過；工具包由研究 repo 修正。
   - 驗收問題的 `subject`、`answer_type` 不在 Markdown 裡。要檢查「能力問題走得到答案」時，你可以在 `.build/cq.yaml` 補上推測，並在回報中列出每一條推測，請人確認。
   - 第 ⑤ 步的 `.build/mappings.yaml` 還沒有轉換程式，依 `docs/05` 的格式由你轉出。
   - 不修改任何 Markdown。
2. **執行工具**：
   ```bash
   python3 tools/check.py --step <目前的步驟>
   python3 tools/derive.py > .build/invariants.derived.yaml
   ```
3. **引用檢查**：
   ```bash
   python3 tools/lint.py <切片>
   ```
   檢查改名後殘留的英文名稱、已取消項目被引用、編號存在、詞彙對照表涵蓋、標記寫法、`inputs/` 路徑、讀取的輸入版本、「提出／同意」的待確認。
   接著對照 `docs/02` 第七節：「方式」欄寫了工具名稱的已經檢查過，不要重做；標「程式」但沒寫工具名稱的，由你逐條比對；標「AI 判斷」的要讀內容判斷。只檢查目前已存在的交付物。
4. **回報**：
   - 結果寫成「結構檢查：紅燈 n 項、未檢查 m 項」，不要只寫「紅燈 0 項」或「通過」。
   - 每項紅燈：哪個檔案、哪一項、建議怎麼修。
   - 每項「未檢查」：缺哪個檔案或沒有資料，是本來就不需要（例：還沒到那一步、沒有子類），還是轉換漏了。
   - 第七節：哪幾項比對過、結果；哪幾項不適用。
   - **這個檢查沒有涵蓋的範圍**：規則條件是否正確、是否與法條原文相符、狀態機是否漏了轉換、屬性能不能撐住多次發生、決定的來源是否寫對。這些要靠挑錯與審查。
   - 推導出的結構不變量數量；有沒有「必要但推不出來」的約束。
   - 轉換時做的推測。
   - `.build/` 不提交。
