# 凍結一個步驟

參數：`$ARGUMENTS`（步驟編號 N、切片代號）。沒有參數時，找出狀態為「待檢查」的交付物；只有一個就用它，有多個就問。

## 1. 確認可以凍結（任何一項不符就停下來說明，不要凍結）
- 交付物狀態是「待檢查」。第 ③ 步要同時看 `03_flows.md` 與 `03_use_cases.md`；第 ⑥ 步看 `06_evidence/signoff.md`。
- 「檢查紀錄」每一列的「審查者確認」都已打勾（✓），或寫了人同意的偏離理由（「預設」類規定可偏離，「必須」類不可，見 `docs/01` 0.2）。
- 「審查者」已填，且不是 AI；「結論」是「通過」。
- 第 ⑥ 步另外確認：`signoff.md` 的執行者與簽核者都已填且不是同一人；黃金案例的預期結果由人填寫。
- 第 ④ 步另外確認：第 ③ 步已凍結。
- 有引用標 `[待專家確認]` 的項目可以凍結，但要在回報中列出。

## 2. 寫入
1. **版本**：`git tag --list '<切片>/0N-v*'` 取最大版本加一，得到 `<切片>/0N-vK`。
2. 交付物開頭區：狀態改「已凍結」，版本填 tag。
3. **切片 `CHANGELOG.md`** 最上面新增一筆（類型：凍結）：改了什麼（初版摘要或本版相對上一版的改變）、依據、反例處理統計、產出者、審查者。
4. **第 ②③④ 步：合併進 `core/`**
   - 本步「新增」的項目，照 `docs/02` 第六節格式寫進對應的 `core/` 檔案，標題列標 `[候選]`，寫出處 `<切片>（<步驟> @ <tag>）`；驗收問題寫成 `<切片>:Qnn`。
   - 本步引用的既有核心項目，在它的「被引用」加上本切片。
   - 詞彙對照表新增區併入 `core/glossary.md`。
   - 規則編號與 `core/rules.md` 撞號時，停下來請人決定重編哪一方。
   - 本步引用了 `core/` 中 `[已取代]` 或 `[已停用]` 的項目時，停下來說明，請人決定改引用取代它的項目。
   - 本步「變更提案」區有已核准的第 3 級變更提案：被取代或停用的舊項目不刪除，標題列與 `core/glossary.md`、`core/relations.md` 對應的列改為 `[已取代: <新 ID>，<生效日>]` 或 `[已停用: <生效日>]`，狀態要一致（`docs/02` 第六節）。
   - `core/CHANGELOG.md` 新增一筆。
   - 第 ⑤ 步：`slices/PLAN.md` 中這條切片的狀態改為「設計完成（待驗證）」，變更紀錄記一筆。
   - 第 ② 步：本切片正式定義的名詞，在 `slices/ENTITY_SKETCH.md` 改為「已定義」，「一句意思」改為「見 core/entities.md」，草圖的變更紀錄記一筆。
5. **第 ⑥ 步：升級核心項目**
   - 本切片出處的 `core/` 項目，若相關的驗收問題、規則、黃金案例都經專家確認 → `[已驗證]`；有 `[暫代]` → `[已驗證（暫代）]`；仍有 `[待專家確認]` → 維持 `[候選]`，並在回報列出原因。
   - `core/CHANGELOG.md` 記一筆（類型：升為已驗證）。
   - `slices/PLAN.md` 中這條切片的狀態改為「完成」，變更紀錄記一筆。

## 3. git
1. 列出要提交的檔案給人看（含本切片新增的 `inputs/` 檔案、`slices/PLAN.md`、`slices/ENTITY_SKETCH.md`）。
2. `core/` 有修改時：依 `docs/01` 0.3，核心的修改要由**核心負責人**核准。
   - repo 有遠端且可用 `gh`：問人要不要開 PR（分支 `core/<切片>-0N-vK`）；同意才開。
   - 沒有遠端：在回報中提醒核心負責人審閱 `core/` 的 diff。
3. commit 訊息：`<切片> 0N 凍結：<一句話摘要>`。
4. 打 tag `<切片>/0N-vK`。
5. 不 push，除非人要求。

## 4. 回報
- tag、提交的檔案、合併進 `core/` 的項目數。
- 仍標 `[待專家確認]`、`[未核對]` 的項目。
- 下一步：`/domain-step <N+1>`。第 ⑤ 步凍結後：這條切片設計完成，可以開始下一條切片；第 ⑥ 步等有系統時再做。第 ⑥ 步凍結後：這條切片完成。
