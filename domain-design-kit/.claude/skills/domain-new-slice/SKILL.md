# 開始一條新切片

參數：`$ARGUMENTS`。

先用一句話說明：「這是開始一條**切片**（一個從起點到可驗證結果的情境），不是開始一整個領域；範圍會在第 ① 步一起細化。」

## 1. 決定是哪一條
- **沒有 `slices/PLAN.md`**：先執行 `/domain-plan`（使用者給了描述，就把描述當作它的參數）。地圖有了再回來。
- **沒帶參數**：列出地圖中狀態為「候選」的切片與建議順序，推薦順序最前、依賴都已完成的那一條，請使用者選。
- **參數是地圖中的代號**：用那一條。
- **參數是一句描述、地圖中沒有對應的切片**：先執行 `/domain-plan <描述>` 把它加進地圖（估大小、領域、依賴、順序），使用者同意後再繼續。
- 選中的切片依賴尚未完成的切片時，告訴使用者，請他決定要先做依賴，還是用靜態替代先做。

## 2. 建立
1. `slices/<代號>/` 已存在 → 停下來，改用 `/domain-status`。
2. `core/` 不存在 → 把 `templates/core/` 複製成 `core/`（第一條切片）。
3. 把 `templates/slice/` 整個複製到 `slices/<代號>/`，所有檔案中的 `{{切片}}` 換成代號。
4. 在 `slices/PLAN.md` 把這條切片的狀態改為「進行中」，「變更紀錄」記一筆。

## 3. 確認輸入
1. 列出 `inputs/<代號>/` 與 `inputs/shared/` 的檔案。
2. 使用者在對話中貼上的訪談、需求：新增為 `inputs/<代號>/` 下的檔案，檔頭寫「使用者於對話中提供，<日期>」。不修改已存在的檔案。
3. 一次問完（已從地圖或輸入得知的就不問）：
   - 這條切片明確不做什麼？
   - 有沒有 Domain 專家或客戶端使用者可以確認？是誰？
   - 依賴但這次不實作的東西，要用什麼靜態替代？
   - 還有沒有訪談紀錄、既有 User Story 可以提供？沒有也可以，AI 會先提出初稿再一起修正。

## 4. 開始第 ① 步
拿到回答後，執行 `/domain-step 1 <代號>`。
