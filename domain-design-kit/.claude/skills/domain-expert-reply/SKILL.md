# 處理專家回覆

參數：`$ARGUMENTS`。也可以處理不在清單上的新意見：先替它新增一個 EQ 編號（提出於「專家主動提出」）。

1. **更新 `questions.md`**：狀態改「已回覆」，填答覆、答覆日。
2. **找出受影響的項目**：該列「影響」欄，加上全切片搜尋 `[待專家確認: EQ-nnn]` 的位置。必要時用 `/domain-check` 後的 `tools/impact.py <名稱>` 擴大範圍。
3. **逐項比對**答覆與目前的設計：
   - **一致**：把 `[待專家確認: EQ-nnn]` 換成「已確認」（驗收問題的「確認」欄寫「已確認」）。若該檔已凍結，記 CHANGELOG（類型：專家回覆）。
   - **不一致**：依 `docs/01` 0.9 的「回頭對照表」判斷要回到哪一步：
     | 答覆的內容 | 回到 |
     |---|---|
     | 名詞的邊界錯了 | ② |
     | 現實流程和設計不同 | ③ |
     | 規則有例外或解釋不同 | ④（需要新的判斷條件時再回 ②） |
     | 新的情境或需求 | ① |
     | 「這不是我要的」（看過 ⑥ 結果） | ① |
   - 切片尚未通過 ⑥ → 第 0 級；已通過 ⑥ 且影響已驗證的核心項目 → 改用 `/domain-change`。
4. **提出方案並停下來**：回到哪一步、要改什麼、依 `docs/01` 0.9「回歸範圍」哪些後續步驟要重新檢查。**等人同意**。
5. 人同意後：
   - 修改被回到的那一步，並在 `CHANGELOG.md` 記一筆（類型：回頭修改（第 0 級）；依據：EQ-nnn；舊 → 新；影響與回歸）。
   - 被修改且原本已凍結的檔案，狀態改回「待檢查」，清空「檢查紀錄」的審查者確認欄，重新填 AI 自評。
   - 依回歸範圍，後續已凍結的步驟中受影響的部分也照此處理；沒受影響的步驟維持凍結。
   - `questions.md` 的「處理」欄寫：回到哪一步、等級、對應的 D 編號或 CHANGELOG 日期。
6. 回報：改了哪些檔案、哪些步驟要重新審查並 `/domain-freeze`。
